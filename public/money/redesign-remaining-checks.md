# お金管理の再設計：UIデザイン前の未完了検査

状態は 2026-10-31 時点。各項目を1件の検査として数える。1件の検査に複数の操作や自動テストが含まれることがある。完了には対象の処理を用意し、記載された条件を確認する。検査を増減するときは理由と変更前後の件数を報告する。

残り **10件**（完了 0 / 10）。合格済みの自動テストとは別の、以下の未完了検査を数える。

1. [ ] **実データ読取の完全性**：権限のある読み取りで家計・口座・取引・メール候補を取得し、欠落・権限エラーを検出する。個人情報はテストデータに保存しない。
2. [ ] **実メールとの照合**：利用カード・金額・利用日時と記録を照合し、不明・重複・未通知は未確認として残す。対象範囲と件数を記録する。
3. [ ] **次の引落の試算**：実データを安全な環境で変換し、各引落口座の残高、未確認事項、計算結果を根拠と照合する。
4. [ ] **90日間の支払い予測**：カード、予定入金、隔月水道代、口座振替と支払日の順序を統合し、不足・未確定を独立した期待結果と照合する。
5. [ ] **締め日までに使える額**：実際の締め日・口座・支払い・未確定収入・内訳を使う新しい計算の仕様と実装を検証し、二重計上や誤解を招く確定表示を防ぐ。
6. [ ] **請求確定・引落の保存**：請求確定で残高を変えず、実引落を記録し、再送・金額相違・残高反映済みに対応できることを保存先で確認する。
7. [ ] **返金・取消とメール重複の保存**：元取引・カード・金額を照合し、確定前後の訂正、重複通知や不明な対象を安全に処理することを確認する。
8. [ ] **定期予定の保存・移行**：旧データと月をまたぐ日付変更を扱い、水道代やカード払いを重複生成・二重計上しないことを確認する。
9. [ ] **移行・復元**：家計と関連データのバックアップ、復元、件数と内容の比較、権限エラー・途中失敗を実際の保存方式で確認する。
10. [ ] **複数端末の同時更新**：同時編集・再送・通信失敗により残高や予定が上書き・二重反映されないことを保存先で確認する。

これらは UI デザイン前の検査であり、UI完成後に必要なスマートフォン実機・表示・操作・公開前チェックの完了を意味しない。既存の試作関数や模擬データだけでの合格を、実データや保存先の検証として数えない。
