# お金管理：本番切替の順序

2026-11-06の読取結果。本番アプリとルールは閲覧のみ。

- 本番のお金管理はv37。`queueSave` は版番号を増やさず、家計のstateを保存する。
- 検証用プレビューはv78。保存時の版番号照合と、開いた編集画面の競合検出を使う。
- 公開中のFirestoreルールは版番号を検査していない。コンソールの最新公開履歴は2026-09-28。
- リポジトリの `firestore.rules` は版番号を必須にする更新案。先に公開するとv37の保存が拒否される。

## 今回完了した検査

検証用家計を2つの独立したChromeタブで開き、一方の保存がもう一方へ届くこと、古いフォームの保存拒否、フォーム内の入力保持、拒否後にクラウドが書き換わらないことを確認した。検査用メモは元へ戻し、残高・業務データ・関連文書の保持も照合済み。

候補ルールの旧クライアント拒否・新クライアント保存・権限拒否は、隔離したFirestoreエミュレータで検査済み。本番ルールの反映確認と通信断確認は別の残件であり、この結果で完了にしない。

## 本番切替時に必要な順序

1. UI・動作の受け入れ確認と、切替範囲について本人の判断を得る。検証用家計での試験許可を本番切替の許可として扱わない。
2. 本番の最新データをバックアップする。端末に未保存の入力がある場合もJSONで残す。
3. 本番向けブランチへ対象変更を取り込み、本人がGitHub Desktopからpushする。VercelのReadyと配信コードの互換性を確認する。
4. 利用する端末で互換版を読み込み、保存方式が更新されたことを確認する。確認中は家計への編集を止める。
5. Firebase Consoleで更新ルールを公開する。`firestore.rules` には、メールの利用時刻・候補の再確定防止・個人購入額の非共有に関する更新もあるため、適用するアプリとの組合せを確認する。
6. 本番で保存・再読込・競合時の拒否を最小限の操作で確認する。検査用家計の仮想引落を本番の実際の引落として転記しない。

本番切替をUI完成後に行うか、保存方式の互換更新を先に行うかは本人へ確認中。選択が決まるまで本番ルールを変更しない。
