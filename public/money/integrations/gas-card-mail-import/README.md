# カード利用メール取込（Google Apps Script）

Galaxy用のAndroidアプリを作らずに、カード会社の「利用速報メール」から取込候補を作る仕組みです。
Gmailに届いたメールをGoogle Apps Scriptが定期的に読み、解析結果だけをFirestoreの取込候補へ保存します。

```text
カード会社の利用速報メール
        ↓
Gmail
        ↓
Google Apps Script（15分おき）
        ↓
解析・重複チェック
        ↓
Firestore  workspaces/{workspaceId}/importCandidates
        ↓
Webアプリの「取込候補」画面で確認
        ↓
ユーザーが取り込んで、正式なカード取引になる
```

端末に依存しないため、Galaxyの省電力設定や再起動の影響を受けません。

## パスワードもAPIキーも不要です

このスクリプトは、**実行するGoogleアカウント自身のOAuthトークン**でFirestoreへアクセスします
（`ScriptApp.getOAuthToken()`）。そのため次のものは一切必要ありません。

- 取り込み専用のFirebaseユーザー
- パスワード
- Firebase APIキー
- サービスアカウントの秘密鍵

スクリプトプロパティに保存するのは、秘密情報ではない `PROJECT_ID` と `WORKSPACE_ID` だけです。
しかもworkspaceが1つだけなら自動検出するので、通常は**何も設定しなくて済みます**。

## 保存するもの・保存しないもの

保存する：解析済みの金額、利用日、カード名の候補、差出人ドメイン、候補の状態、fingerprint

保存しない：**メール本文の全文、カード番号（下4桁を含む）、口座番号、認証コード、氏名・住所**

ログにも本文を出力しません。`setup()` や `dryRun()` の出力にも本文は含めません。

## セットアップ手順

### 1. カード会社の利用速報メールを有効にする

各カード会社の会員サイトで「カード利用お知らせメール」「ご利用速報」などを有効にします。
**金額と利用日が本文に載る設定**にしてください。件名だけの通知だと解析できません。

### 2. Apps Scriptプロジェクトを作る

1. https://script.google.com/home/projects/create を開く
2. プロジェクト名を「カード利用メール取込」などに変更
3. 左の「エディタ」で次の3ファイルを作る

| ファイル名 | 中身 |
| --- | --- |
| `Code.gs` | このフォルダの `Code.gs` |
| `Parsers.gs` | このフォルダの `Parsers.gs` |
| `appsscript.json` | このフォルダの `appsscript.json` |

`appsscript.json` は既定では隠れています。
**プロジェクトの設定 → 「`appsscript.json` マニフェスト ファイルをエディタで表示する」にチェック**を入れると出てきます。

### 3. Google Cloudプロジェクトに紐づける

プロジェクトの設定 → Google Cloud Platform（GCP）プロジェクト → 「プロジェクトを変更」

```text
プロジェクト番号: 529145553530
```

これは `cash-manege` のプロジェクト番号です。紐づけておくと、承認画面に
「このアプリは確認されていません」の警告が出なくなります。

> 紐づけずに進めることもできます。その場合、承認画面で
> 「詳細」→「（プロジェクト名）に移動（安全ではないページ）」を選んでください。
> 自分が書いたスクリプトなので問題ありません。

### 4. 権限を承認して動作確認する

エディタ上部の関数選択で **`setup`** を選び、実行します。

初回は権限の承認画面が出ます。次の権限を求めます。

| 権限 | 用途 |
| --- | --- |
| Gmailの表示と変更 | 利用通知メールを読み、処理済みラベルを付ける |
| 外部サービスへの接続 | Firestoreへの書き込み |
| Google Cloudのデータストア | Firestoreの読み書き |
| スクリプトの実行 | 定期実行トリガー |

承認後、実行ログに次のような内容が出ます。

```json
{
  "firestore": "OK（プロジェクト cash-manege）",
  "workspaceId": "自動検出されたID",
  "gmailMatched": 3,
  "parsed": [
    { "差出人": "楽天カード", "利用日": "2026-08-24", "金額": 1234,
      "カード": "メインカード", "種別": "purchase", "状態": "pending" }
  ]
}
```

- `gmailMatched` が 0 → 速報メールが届いていないか、検索条件が合っていません（下の「検索条件の調整」へ）
- `金額` や `利用日` が空 → 解析ルールの追加が必要です（下の「解析ルールの追加」へ）

### 5. 1回だけ手動で取り込む

関数選択で **`importCardMails`** を選んで実行します。
Webアプリ（https://cash-manege.web.app/）の設定 → 「メールからの取込候補」に表示されれば成功です。

### 6. 定期実行を設定する

左メニューの時計アイコン（トリガー）→ 「トリガーを追加」

```text
実行する関数        importCardMails
イベントのソース    時間主導型
時間ベースのトリガー 分ベースのタイマー
時間の間隔          15分おき
```

無料のGmailアカウントのトリガー実行時間は1日90分までですが、15分おきでも1日8分程度なので十分収まります。

## 検索条件の調整

既定では直近7日の、それらしい件名または主要カード会社のドメインからのメールを探します。
うまく当たらない場合は、スクリプトプロパティ `GMAIL_QUERY` にGmailの検索式を設定してください。

```text
newer_than:7d from:info@mail.rakuten-card.co.jp
```

Gmailの検索窓で同じ式を入れて、目的のメールだけが出ることを先に確認すると確実です。

## 解析ルール

実際に届いたメールの構造に合わせて、次の3段階で金額を特定します。

1. カード会社ごとの専用ルール（`ISSUERS` の `amount`）
2. **「【ご利用金額】 279円」のようにラベルが付いた金額** ← JCB・エポス
3. **利用日時ラベルの直後に最初に現れる金額** ← 三井住友カード（金額にラベルが無い形式）

2か3で特定できた場合は、本文に他の数字があっても自動確定します。
どれにも当たらず金額が複数ある場合だけ `needs_review`（要確認）にします。

### 差出人ドメインの注意

会社名とメールのドメインが一致しません。実際に確認したものは次のとおりです。

| カード会社 | 実際の差出人ドメイン |
| --- | --- |
| 三井住友カード | `vpass.ne.jp`（`smbc-card.com` ではない） |
| エポスカード | `01epos.jp`（`eposcard.co.jp` ではない） |
| JCB | `jcb.co.jp` |

### カード会社を足す

`Parsers.gs` の `ISSUERS` に1件足すだけです。必要なら専用の正規表現を上書きします。

```js
{ domain: 'example-card.co.jp', label: '○○カード',
  amount: /ご利用額[：: ]*([0-9,]+)/,
  cardHint: /カード名[：: ]*([^\n]{1,20})/ }
```

**実物のメールを確認するまで、推測でルールを固定しないでください。**
未対応の差出人でも汎用ルールで金額と日付を拾い、確信が持てないものは `needs_review`（要確認）として保存されます。破棄はしません。

## 重複防止

差出人ドメイン・金額・利用日・種別・件名の正規化値からfingerprintを作り、これをFirestoreのドキュメントIDに使っています。
同じメールが再送されても、候補は1件しか作られません（2回目以降はHTTP 409で重複として扱います）。

## 安全側に倒す条件

次の場合は自動確定せず、`needs_review`（要確認）にします。

- 金額を読み取れない
- 金額が複数含まれる
- 返金・取消の可能性がある
- 差出人が未対応のカード会社

いずれの場合も、Webアプリで承認するまで「今使える金額」にも「支払い能力チェック」にも反映されません。

## 関数一覧

| 関数 | 用途 | Firestoreへ書き込むか |
| --- | --- | --- |
| `setup` | 初回の権限承認と接続確認 | 書き込まない |
| `dryRun` | 解析結果だけを確認 | 書き込まない |
| `importCardMails` | 実際の取り込み。トリガーで呼ぶ | 書き込む |
