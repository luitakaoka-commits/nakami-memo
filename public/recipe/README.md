# つくりおきノート

レシピと献立を管理するモバイル優先のWebアプリ（PWA）。
データはFirebaseのアカウントに保存され、スマホでもパソコンでも同じ内容が見られます。
電波のないところでも閲覧・編集でき、つながったときにまとめて同期されます。

セットアップ手順は **[SETUP.md](SETUP.md)** を参照してください。

## 画面

| タブ | できること |
| --- | --- |
| レシピ | 一覧（分類での絞り込み・並べ替え）、登録・編集・削除、写真、「作った」記録 |
| 献立 | 日付と時間帯ごとに、レシピとレシピ以外の一品をまとめて保存・編集・削除 |
| 買い物 | レシピの材料をまとめて投入、手入力での追加、購入チェック、購入済みの一括削除 |
| 検索 | キーワード検索（検索範囲とAND/ORを設定可能） |
| 設定 | アカウント、アクセントカラー、保存件数、JSONの書き出し／読み込み、全削除 |

## 構成

```
index.html              画面の器（外枠だけ。中身はJSが描く）
app.js                  画面の描画と操作。ESモジュール
firebase.js             Firebaseの初期化と認証
firebase-config.js      プロジェクト固有の設定値（各自で差し替える）
store.js                Firestore / Storage の読み書き
style.css / tokens.css  見た目（tokens.cssに色と形の定義）
sw.js                   オフライン起動用のService Worker
manifest.webmanifest    ホーム画面に追加するための定義
firestore.rules         本人のデータだけ読み書きできるルール
storage.rules           写真は本人のみ・5MBまでの画像に限るルール
firebase.json           Hosting・ルール・エミュレータの設定
```

ビルド工程はありません。Firebase SDK は gstatic のCDNから読み込み、
Service Worker がキャッシュするので、2回目以降はオフラインでも起動します。

## データの持ち方

```
users/{uid}/recipes/{recipeId}    レシピ本体（写真はStorageのURLを持つ）
users/{uid}/plans/{planId}        献立（日付・時間帯・レシピ・追加の一品・メモ）
users/{uid}/shopping/{itemId}     買い物リスト
```

Storage は `users/{uid}/recipes/{recipeId}.jpg`。写真は保存時に長辺1080pxのJPEGへ縮小します。

テーマカラー・並び順・検索条件は端末ごとの好みなので、Firestoreには同期せず
localStorageに置いています。

書き込みはサーバーの応答を待たずに進みます。Firestoreのローカルキャッシュが
先に反映するため、オフラインでも操作が止まりません。

## 意図的に入れていないもの

課金・グループ共有・レシピサイトのURL解析・写真からの自動読み取り・AIによるレシピ生成。
動かない導線を画面に置かない方針です。
