# くらしノート UI点検と統一案（改訂版）

対象は、お金管理・なかみメモ（在庫）・つくりおきノートの3アプリ。
根拠は各アプリのCSS変数と共通スタイル（tokens.css / globals.css / style.css / app-switcher.css）の実測値。
この文書はデザインの下準備であり、実装は行っていない。

**改訂について**：初版では、お金管理の本番デザイン「M5」を統一の基準にしていた。本人の指摘により、基準を最新のお金管理UIプロトタイプ（`public/money/ui-prototype/`、以下「最新プロトタイプ」）に差し替えた。3アプリが別々のデザインシステムで作られているという診断（1〜2章）はそのまま有効で、統一案（4章以降）を書き直している。

## 1. 事実：3アプリは別々のデザインシステムで作られている

| 項目 | お金管理（本番・M5） | なかみメモ在庫 | つくりおきノート |
|---|---|---|---|
| 背景 | 濃色 `#421f2a`（バーガンディ） | 明色 `#edf2ef`（薄い緑灰） | 明色 `#f4f4f4`（中立グレー） |
| 面（カード） | 生成り `#fff8eb` / `#faf2e2` | 純白 `#ffffff` | 純白 `#ffffff`、暖色 `#fffdf8` |
| アクセント | `#713745`＋金 `#d7bc8a` | 緑 `#1e8a58` | アンバー `#e7a400` |
| 文字色 | `#482b30`（赤みのある墨） | `#32443d`（緑みのある墨） | `#242424`（無彩色） |
| 角丸 | 7px / 小 5px | 9px / 14px / 20px | 8px / 10px / サムネイル 6px |
| 見出し書体 | 明朝（Noto Serif JP） | システムサンセリフ | Noto Sans JP |
| 数字書体 | DM Sans（専用指定） | なし（本文と同一） | なし（本文と同一） |
| 影の考え方 | 罫線＋柔らかい影（`0 2px 0 罫線色, 0 9px 22px`） | ほぼ影なし（`0 1px 2px`）＋浮遊時のみ強い影 | 影は使わず境界線で代用（シートのみ上向きの影） |
| 動き | 240ms / 独自イージング | 140ms・220ms / 別のイージング | 150〜200ms / さらに別のイージング |
| フォーカス表示 | 銅色系 `#b77d4c` | 青の輪 3px ＋ 緑のリング（2系統併用） | アクセント濃色の輪 2px |

事実として、色・角丸・書体・影・動きの全項目で3通りの値が併存している。共通しているのは後述のアプリ切替バーだけである。

## 2. 診断：「ぐちゃぐちゃ感」の正体（解釈）

### 2-1. 世界観が3つある
お金管理（本番）は濃色の背景に生成りの面、在庫は深緑のサイドバーとガラス質ヘッダーの業務ツール風、つくりおきはアンバーの温かいカード一覧。アプリを移動するたびに背景色の明暗まで反転するため、同じスイートだと感じにくい。

### 2-2. 画面の文法（レイアウトの型）が違う
- お金管理：ホームの最上部に「いちばん大きな文字で1つの問いへの答え」を置き、その下に日次の数字を続ける型。最新プロトタイプでは、シート（白い面）を縦に積む型に置き換わった（3章）。
- 在庫：コマンドバー（大きな見出し＋検索）→ 統計4件の横並び → セクション見出し＋カードリスト、というダッシュボード型。
- つくりおき：上部バー＋チップ行＋行リスト＋FAB＋下部ナビ、というモバイルリスト型。
情報の優先順位の付け方そのものがアプリごとに異なる。

### 2-3. 状態の表し方が違う
- お金管理：色に頼らず「安全」「要確認」のような短い文言ラベルで状態を示す。最新プロトタイプでは、淡色の背景＋意味色の文字のチップ（`.status`）に形が定まった。
- 在庫：緑・青・アンバー・赤・グレーの色付きピル（バッジ）で示す。色が主、文字は補助。
- つくりおき：選択中はアクセントの淡色背景、完了リストは全体を透明度0.62に落とす、という面と透明度での表現。
期限や残量のような「状態」が中核のアプリ同士で、この表現方法が揃っていない。

### 2-4. 余白と寸法に共通の物差しがない
- 在庫とつくりおきには、余白の段階（スペーシングスケール）を定めた変数がない。在庫の余白は 13px・15px・22px・28px など割り切れない値が多く、つくりおきも 10px・14px・18px などが混在する。
- フォントサイズも、在庫は clamp と小数rem、つくりおきは 10〜23px のpx直書きで、文字の段階が揃っていない。
- 最新プロトタイプは `6 / 12 / 20 / 28px` の4段階スケールを変数化しており、この差がそのまま物差しの有無になっている。

### 2-5. 同じ部品が別々に実装されている
「使った／使えた量を記録する行」が好例。在庫は `.ui-restock` / `.ui-use-row`、つくりおきは `.stock-row` / `.quick-use` と、同じ概念の部品が名前も見た目も別に存在する。チップも在庫はピル型（半径999px）、つくりおきは角丸8pxと形が違う。

### 2-6. アプリ切替バーが唯一の共通要素だが、それ自体も3アプリのどれとも一致していない
切替バーの色は緑系3色（お金 `#14402f`、なかみ `#1f5c43`、レシピ `#8a6a1f`）で、お金管理の本番色バーガンディ `#421f2a` / `#713745` とも、最新プロトタイプの色とも異なる。つまり「共通の顔」であるはずの部品が、4つ目のデザイン言語になっている。切替バーだけがダークモード対応している点も他と揃っていない。

### 2-7. 細部のノイズ（追加で見つけた点）
- 在庫の変数は約60個あり、近似した重複が多い。例：`--red-line #efcaca` と `--danger-line #f0caca`、サイドバーの罫線3段階（透過度 0.13 / 0.18 / 0.34）、文字の透過度3段階（0.72 / 0.76 / 0.84）。
- 在庫では `.ui-qr-card` と `@keyframes ui-spin` が同一ファイル内で二重に定義されている。
- 在庫のフォントウェイトは 620・650・680・720・740・760・780 と細かく散らばり、太さの段階として機能していない。
- つくりおきは変数化が途中で、トースト `#2b2925`、通知帯 `#4a463f`、危険色のホバー `#fdf1ef`、シートの角丸14px（変数は10px）など直書きが残る。
- レスポンシブの境界も在庫 960/820/600px、つくりおき 380px＋本文幅680px と別々。

## 3. 基準の訂正：最新のお金管理UIはプロトタイプ側

統一の基準は、本番の M5 ではなく最新プロトタイプである。両者の違いは次のとおり。

| 項目 | 本番・M5 | 最新プロトタイプ |
|---|---|---|
| 背景 | 濃色 `#421f2a` の上に生成りの面 | 明色。紙 `#fffdf8` の上に白い面 |
| 書体 | 見出しは明朝、数字は DM Sans | Kiwi Maru のみ。本文400、項目・見出し500。数字も同じ書体の等幅数字 |
| バーガンディ `#713745` | 面と文字の主役級 | アクセント専用（日付ラベル、ボタン、チップの基準色） |
| 角丸 | 7px / 5px | シート 20px、コントロール 10px |
| 影 | 罫線＋柔らかい影が中心 | 影はほぼ使わず、シートは1pxの罫線 `#dfd6c9` で区切る |
| 余白 | スケールの変数なし（`--daily-space: 24px` のみ） | 4段階スケール `6 / 12 / 20 / 28px` を変数化 |
| 画面遷移 | 下部タブを含む構成 | 下部タブなし。上部固定の細いヘッダー＋左から出るモーダルサイドバー（`dialog`） |
| 状態表示 | 文言ラベル中心 | 文言＋意味色のチップ（収入・注意・危険の3色と淡色背景） |
| 動き | 240ms / `cubic-bezier(.2,.75,.2,1)` | 同じ 240ms / 同じイージング。ここだけは最初から一致している |

初版のモックは M5 の濃色・明朝・角丸7pxで作っていたため、基準の差し替えに合わせて作り直した。動きの値だけは両者で共通なので、統一コストは見た目ほど大きくない。

## 4. 統一案：最新プロトタイプを共通言語にする

### 4-1. 共通ルール（8つ）
1. **色**：背景は紙 `#fffdf8`、面は白 `#ffffff`、罫線は `#dfd6c9`、文字は `#352c2b`、補助は `#71645f`。バーガンディ `#713745` はアクセント専用にし、面の主色には使わない。
2. **形**：シートの角丸は 20px、コントロールは 10px。シートの区切りは1pxの罫線で、影は使わない（浮く要素だけ例外）。
3. **余白**：`6 / 12 / 20 / 28px` の4段階だけを使う。シート内余白は 20px、シート間は 20px。
4. **文字**：Kiwi Maru のみ。本文は 400、項目・見出し・ボタンは 500。数字は同じ書体の等幅数字（`tabular-nums`）で揃える。専用フォントは増やさない。
5. **階層**：ホームはシートの積み重ねにする。各シートは「小さな見出し（12px・補助色）→ 日付や対象のラベル（ブランド色・14px・500）→ 大きな数字（最大56px）」の順で読ませる。
6. **状態**：チップで示す。淡色の背景＋意味色の文字、角丸 10px、12px。意味は3色に固定する。収入・正常は `#276457`（淡色 `#edf5f1`）、注意は `#865316`（淡色 `#fff3dc`）、危険は `#a3373b`（淡色 `#fff0ef`）。状態を透明度で表す方法は廃止する。
7. **遷移**：下部タブは置かない。上部固定の細いヘッダー（メニューボタン44px＋画面名＋アプリ名のキャプション）と、左スライドインのモーダルサイドバーに統一する。
8. **文言と動き**：画面の文章は必要最小限にする（プロトタイプREADMEの本人の方針）。説明文や注意書きを足さない。動きは 240ms / `cubic-bezier(.2,.75,.2,1)`。

### 4-2. なかみメモ在庫への当てはめ
- ホーム先頭のシート：「期限が近いもの」を小さな見出しにし、件数を大きな数字で置く。内訳（今日まで◯件など）は補助文字1行まで。
- 期限の状態はチップに写す。期限切れ＝危険、今日まで・明日まで＝注意、あと3日など近いもの＝注意のチップか補助文字、余裕あり＝チップなしの静かな文字にする。在庫の色付きピル（5色）は廃止する。
- 一覧の行は明細行（ledger）の形にする。左に品名と場所の補助ラベル（冷蔵庫・冷凍庫、12px・補助色）、右に数量とチップを右寄せで置く。
- 期限リストは緊急度のグループ見出し＋シートで区切り、各グループの件数はブランド色の件数表示（check-row の形）に寄せる。
- ダッシュボードの統計4件横並びは、先頭シートの「大きな数字＋補助数字」に整理する。常設サイドバーとガラス質ヘッダーは、ヘッダー＋モーダルサイドバーの形に置き換える。
- 変数は約60個から、プロトタイプと同規模（色・余白・角丸・動きで約30個）まで削る。近似色の重複と二重定義は統一のついでに解消する。

### 4-3. つくりおきノートへの当てはめ
- ホーム先頭のシート：「今ある作り置き」の品数を大きな数字で置く。合計食分は補助文字にする。
- 料理の行は明細行の形にする。左に料理名と場所、右に「残り◯食分」と「あと◯日」を右寄せで並べ、期限の状態は在庫と同じチップの語彙（今日まで＝注意、余裕あり＝静かな文字）で示す。
- レシピ詳細は1枚のシートにする。料理名を大見出し（500）にし、材料は明細行（左に材料名、右に分量）で罫線区切りにする。手順は番号付きの行にする。明朝や点線リーダーは使わない。
- FABは、ブランド色のプライマリボタンに置き換える。下部ナビは廃止し、遷移はヘッダー＋サイドバーに寄せる。
- アンバーの全面使用はやめる。直書きの色（トースト、通知帯など）は変数に移す。

### 4-4. アプリ切替バーの扱い
切替は、サイドバーのメニュー項目として取り込むのがプロトタイプの文法に沿う。残す場合も、色はプロトタイプの色（紙・白・ブランド色）に合わせ、現状の緑系パレットは廃止する。

## 5. あわせて引き継ぐもの（見た目以外の仕様）

最新プロトタイプには、見た目とセットで決まっている操作と表示の仕様がある。統一ではこれも引き継ぐ。

- **ダイアログの型**：詳細と編集は `dialog` 要素のモーダルダイアログにする。幅は `min(90vw, 480px)`、高さは最大 `85dvh`、角丸 20px、背景はベール `#241b25a3`。背景タップ・閉じるボタン・Escapeで閉じ、閉じたらフォーカスを開いた要素へ戻す。開いている間は背面のスクロールを止める。
- **フォーカス表示**：`:focus-visible` にブランド色 3px の輪＋4px のオフセット。全アプリで1系統にする（在庫の青＋緑の2系統、つくりおきの2pxは廃止）。
- **タップ領域**：ボタンと選択肢は最小高さ 44px、メニュー項目は 48px。入力欄も 44px を確保し、文字サイズは 16px（拡大表示の誤作動防止）。
- **safe-area**：ヘッダー上部とダイアログ下部に `env(safe-area-inset-*)` を使う。
- **動きを減らす設定**：`prefers-reduced-motion: reduce` でアニメーションと遷移をすべて止める。サイドバーのスライドインも対象。
- **表示状態の網羅**：通常・不足（空に近い）・データなし・読み込み中・オフライン・エラー・保存完了の7状態を、画面ごとに用意する。読み込み中はスケルトン（淡色の帯）で示す。
- **通知の出し方**：操作結果はトースト（画面下部、墨色の面）で短く知らせ、スクリーンリーダー向けには視覚的に隠したライブリージョン（`aria-live`）でも伝える。
- **本文幅**：本文は最大 600px で中央寄せ。350px 以下の狭い幅では余白を一段小さくする。

## 6. 未決事項：色まで完全に統一するか（再整理）

初版では、案A（色・形・文字・文法のすべてを統一）と案B（文法だけ統一し、アクセント色はアプリごとに残す）を比べた。基準が最新プロトタイプに変わり、この対立はほぼ消えた。

- プロトタイプは明色の紙の上に白いシートを置き、バーガンディをアクセントに絞っている。背景の明暗という「世界の差」は、基準側にそもそも存在しない。
- 残る論点は、在庫の緑やつくりおきのアンバーという固有色を、アクセントとして残すかどうかだけになる。
- 推奨は、固有色は残さず、色はプロトタイプの1系統に統一すること。アプリの区別は、サイドバーの現在地表示と見出しの文言で足りる。意味色（収入・注意・危険）は3アプリ共通の約束事として固定する。

## 7. 添付
`design-board.html` に、最新プロトタイプの言葉で作り直した画面案（在庫ホーム／期限リスト／作り置きホーム／レシピ詳細）を置いた。実装前の確認用。
